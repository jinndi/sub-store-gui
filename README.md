# Sub-Store Desktop

Настольный клиент Sub-Store, готовый к использованию сразу после установки. Приложение запускает официальный frontend и backend Sub-Store локально через Electron и не требует от пользователя установки Node.js, Docker или расширений для браузера.

## Текущие возможности

- Встроенные официальный GUI и Node.js backend Sub-Store
- Прослушивает только `127.0.0.1`, не предоставляя доступ из локальной сети
- Использует случайный API-путь и ограничивает источники CORS для backend
- Подписки, объединённые подписки, скрипты, файлы и настройки синхронизации сохраняются в системном каталоге данных приложения
- Конфигурация сборки для Windows, macOS и Linux (x64 и ARM64)
- Фиксированные версии upstream-компонентов с проверкой SHA-256

Текущие зафиксированные версии: Sub-Store `2.37.1`, Sub-Store Front End `2.31.0`. Подробнее см. [`vendor-lock.json`](vendor-lock.json).

## Архитектура

```text
Electron Main Process

  ├─ BrowserWindow (песочница включена, доступ к Node.js отсутствует)
  │
  └─ Utility Process
       │
       └─ Официальный bundle Sub-Store
            ├─ Локальный статический frontend
            ├─ Локальный API
            └─ Каталог данных пользователя
```

Проект использует структуру с двумя `package.json`, поддерживаемую electron-builder: корневой каталог отвечает за разработку и сборку, а `app/package.json` представляет собой минимальный runtime-пакет без зависимостей для разработки.

Frontend и API используют один случайный локальный порт. API дополнительно размещается по случайному пути, который генерируется при первом запуске. Порт и путь сохраняются в `desktop-runtime.json`, доступном для чтения только текущему пользователю.

## Разработка

Требуется Node.js 22 или выше.

```bash
npm install

npm run dev
```

При первом запуске `npm run dev` загружает зафиксированные официальные дистрибутивы, указанные в `vendor-lock.json`, и выполняет их проверку. Также можно выполнить команды отдельно:

```bash
npm run vendor:sync

npm run vendor:verify

npm test
```

## Сборка

В соответствующей операционной системе выполните:

```bash
npm run dist:win

npm run dist:mac

npm run dist:linux
```

Готовые файлы находятся в каталоге `release/`.

GitHub Actions выполняет сборку на трёх нативных операционных системах, создавая установочные пакеты для x64 и ARM64.

Перед официальным распространением необходимо заменить placeholder-адрес электронной почты сопровождающего в `package.json` на адрес электронной почты проекта, а также настроить подпись кода для Windows и Apple Developer ID/нотариальное заверение для macOS. Неподписанные установочные пакеты могут вызывать предупреждения системы безопасности.

## Данные пользователя

Приложение не записывает данные подписок в каталог установки. По умолчанию используется каталог `userData`, определяемый Electron:

- Windows: `%APPDATA%/Sub-Store Desktop/sub-store/data`
- macOS: `~/Library/Application Support/Sub-Store Desktop/sub-store/data`
- Linux: `~/.config/Sub-Store Desktop/sub-store/data`

При удалении приложения через NSIS пользовательские данные по умолчанию сохраняются.

Логи находятся в том же каталоге `userData`, в `logs/sub-store.log`. При превышении размера 5 MiB сохраняется одна резервная ротационная копия журнала.

## Обновление upstream-версий

Измените версии, URL и значения контрольных сумм в `vendor-lock.json`, после чего выполните:

```bash
npm run vendor:sync

npm run vendor:verify
```

Не добавляйте в Git бинарные дистрибутивы из `resources/vendor`. CI повторно загружает их из lock-файла и выполняет проверку.

Установочный пакет также содержит соответствующий исходный код этого проекта и тексты лицензий upstream-компонентов. Пользователь может напрямую открыть каталог с исходным кодом через меню «Справка» в приложении.
